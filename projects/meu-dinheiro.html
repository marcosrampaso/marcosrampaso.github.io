The problem

Bank statements, card invoices, and investment positions arrive in different formats and use different reference dates. A transfer can look like income, and a card payment can be counted again as spending. Organizing these records requires both extraction and reconciliation.

The application

Meu Dinheiro brings these sources into a Python application with a browser interface and a macOS desktop preview. Its JSON API supports transaction management, import review, monthly charts, planning, and investment views. Personal and business activity can be explored separately.

Decisions that matter

Review before import

Imports show a preview before saving. Duplicate detection, statement coverage, and reconciliation rules help keep overlapping files and internal transfers from distorting the totals.

Consistent amounts and dates

Transaction amounts are stored in integer cents. Card billing periods and transaction dates are treated separately, and gaps in statement coverage remain visible.

Separate account data

Local accounts use separate databases and credential directories. The authenticated server session determines the active account, and the demonstration uses temporary fictional data.

AI with human review

Optional categorization suggestions can be reviewed before they are applied. Approved categories inform local matching. The demonstration blocks bank connections and external AI calls.

Integrations and delivery

The project includes authorized bank-data integration through Pluggy, investment imports, and public market-data connections. A macOS WebKit wrapper starts the local Python backend. The desktop package excludes local databases and credentials.

AI tools supported implementation and investigation throughout development.

Validation and current limits

The repository includes automated tests covering financial calculations, imports, API behavior, and account isolation. A temporary demonstration environment uses fictional records and blocks external bank and AI connections.

  • The application runs locally. It is not presented as a hosted multi-user SaaS product.
  • Text-based PDFs are supported; scanned PDFs require an OCR step.
  • SQLite files are not encrypted by the application.
  • The macOS desktop preview still requires Developer ID signing and notarization for conventional public distribution.
  • Bank integrations depend on provider access and user authorization.
The source repository is private. No personal financial records, bank documents, credentials, or installer are included in this portfolio.
